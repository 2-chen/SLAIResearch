# 研究构思框架（10 个结构化方法）

摘自 NanoResearch-slai `brainstorming-research-ideas` 技能。当你还没有明确研究方向时，可以从任意框架入手。

## 框架速查

| 你的状态 | 从哪开始 |
|---------|---------|
| 不知道做什么领域 | 3. 矛盾狩猎 → 5. 什么变了 |
| 有模糊领域没有具体想法 | 2. 抽象阶梯 → 6. 失败分析 |
| 有想法但不确定好不好 | 10. 解释测试 → 7. 简单性检验 |
| 有好想法想要新角度 | 4. 跨领域迁移 → 8. 利益相关者轮换 |
| 想组合现有工作 | 9. 组合与分解 |
| 想挑战传统智慧 | 6. 失败分析 → 7. 简单性检验 |

## 1. 问题优先 vs 方案优先

- **问题优先**：从痛点出发 → 找方法。风险：增量改进
- **方案优先**：从新能力出发 → 找应用。风险：拿着锤子找钉子

自检：能说出谁会受益吗？问题真的没解决还是只是宣传不够？

## 2. 抽象阶梯

- **上移**（泛化）：从具体结果提炼普遍原理
- **下移**（实例化）：在极端约束下测试通用范式
- **侧移**（类比）：将同层抽象应用到相邻领域

## 3. 矛盾与张力狩猎

常见研究张力：
- 性能 ↔ 效率：能否用 1/10 算力匹配 SOTA？
- 隐私 ↔ 效用：联邦/加密方法能否缩小精度差距？
- 通用性 ↔ 专用性：微调何时优于提示？
- 安全性 ↔ 能力：对齐能否促进而非牺牲能力？
- 可解释性 ↔ 性能：机制理解能否带来更好的架构？
- 规模 ↔ 可及性：小模型能否复现涌现行为？

## 4. 跨领域迁移

从其他学科借结构：
- 神经科学 → 注意力、记忆巩固
- 物理学 → 能量模型、相变
- 经济学 → 机制设计、拍卖理论
- 生态学 → 种群动态、生态位竞争
- 语言学 → 组合性、语用学
- 控制论 → 反馈回路、稳定性

## 5. "什么变了？" 原则

旧想法在新条件下可能变成好想法：
- **算力** 10× 提升 → 以前太贵的方法现在可行
- **数据** 规模增长 → 小数据上失败的统计论证可能现在成立
- **法规** 变化 → GDPR/AI Act 催生合规替代方案需求
- **工具** 进化 → 新框架降低实现门槛
- **失败案例** → 揭示现有方法的缺口

## 6. 失败分析与边界探测

系统性地找到方法失效的条件：
- 分布外输入
- 10× / 0.1× 典型规模
- 对抗攻击
- 组合多个能力
- 概念漂移

## 7. 简单性检验

问自己：更简单的方法能行吗？
- 该方法有很多超参数且最优范围窄？
- 消融实验显示大部分组件只有边际贡献？
- 简单基线从未被认真调参？
- 对基线的提升在大多数基准上都在噪声范围内？

## 8. 利益相关者轮换

从不同视角看系统：
- **终端用户**：可用吗？什么错误不可接受？
- **开发者**：可调试吗？维护负担多大？
- **理论家**：为什么有效？形式化保证在哪？缺口在哪？
- **攻击者**：怎么利用？攻击面在哪？
- **伦理学家**：谁被伤害？什么偏见嵌入了？
- **监管者**：可审计吗？能解释决策吗？

## 9. 组合与分解

- **组合**：两个互补子问题的方法合并 → 什么涌现能力出现？
- **分解**：拆解复杂系统 → 哪个组件是真正的瓶颈？

## 10. "解释给外人听" 测试

两句话模板：
> 第 1 句（问题）：[领域] 目前受困于 [具体问题]，这很重要因为 [具体后果]。
> 第 2 句（洞察）：我们通过 [关键机制] 来 [方法]，这有效是因为 [原因]。

如果填不出这两句话 → 想法还不够清晰。
